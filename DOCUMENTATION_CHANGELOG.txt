DOCUMENTATION CHANGELOG (Updated: 2026-09-01)
=========================================================
This document provides a detailed breakdown of the architectural and system documentation updates applied to the ARQuest project. These changes align the project's documentation with the newly implemented 3D Compression Pipeline, Mobile AR optimizations, and updated database schemas.

1. README.md
   - Core Features Expansion: Highlighted the flagship Node.js/Python 3D compression pipeline, explicitly noting its capability to reduce massive 2GB+ CAD models down to ~30MB using Mesh decimation, chunk partitioning, and Google Draco quantization.
   - AR Navigation Updates: Updated the Spatial AR bullet point to emphasize the new high-performance 60FPS tuning, smoothed gyroscope deadbanding, and dynamic off-screen route HUD indicators.

2. conceptual-framework.md
   - IPO Model Adjustments: Updated the Process block (P5) within the Mermaid flowchart to include the "3D Compression Pipeline (Decimation, Draco, Partitioning)".
   - Mechanism Details: Elaborated on the Mobile AR Raycast Throttling and "Smart Spawn" mechanics in the supporting text to explain how the system prevents users from falling through the map (void-falls) during 3D virtual tours.

3. context-diagram.md
   - System Node Expansion: Updated the central "ARQuest System" boundary node in the Context Diagram to explicitly list the integrated technologies: React Native / ViroReact Mobile, Web Dashboard, Django / Node.js 3D Compressor, PostgreSQL, and AWS S3. This provides a more accurate view of the system's runtime environments and storage dependencies.

4. data-flow.md
   - New Sequence Diagram (Flow 9): Added a completely new sequence diagram titled "Admin 3D Compression Pipeline Flow". 
   - Flow Details: This flow traces the exact API interactions when an Admin uploads a 1.6GB+ 3D model, detailing the transition through the Node.js/Draco compressor, Meshoptimizer application, and the final direct-to-S3 binary upload.

5. system-architecture.md
   - Backend Layer (Layer 2): Rewrote the architecture description to incorporate the glTF-Transform and Meshoptimizer pipeline.
   - Data Layer (Layer 4): Updated the storage architecture to reflect AWS S3 binary staging instead of pure local storage, eliminating bandwidth bottlenecks for heavy 3D assets.
   - Mobile Layer (Layer 1): Updated the Three.js and ViroReact descriptions to reflect the 60FPS collision raycasting limits and smart ground-floor spawning optimizations.

6. erd.md (Entity Relationship Diagram)
   - Buildings Table: Added new schema attributes model_size (float) and model_active (boolean) to track the compression status and byte footprint of building assets.
   - User Preferences: Documented the full UserSetting fields including haptics_enabled, sfx_enabled, and distance_unit.

7. erd-model.md (Conceptual ERD)
   - Entity Updates: Updated the visual Chen's notation / Mermaid ERD mapping for the BUILDING entity to visually include the new tracking attributes (model_size, model_active) required by the 3D compressor engine.

8. use-case.md
   - Admin Capabilities: Added Use Case 22 (UC22: "Run 3D Compressor Pipeline") to the Admin Web Dashboard boundary.
   - Student Capabilities: Augmented Student use cases (UC3, UC5) to specify the usage of 60FPS AR navigation and smart-spawn virtual tours.

9. user-flow.md
   - Spatial AR Flow: Updated the Mobile Spatial AR flowchart paths to trace the conditional rendering of off-screen turn indicators when destinations fall outside the camera's FOV.
   - Virtual Tour Flow: Updated the 3D walkthrough flowchart to include the "Smart Ground Floor Raycast Spawn" step, ensuring the player is safely grounded prior to initializing the Three.js interior renderer.
